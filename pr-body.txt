## Scope Note

This PR packages the validated Etsy/shop OAuth backend work for Phase 1.

**Why issue #9?** The original issue #9 was for queue planning/BOM consolidation, but during implementation it became clear that the Etsy shop connection foundation (OAuth, listing sync, token management) was a prerequisite for meaningful queue planning. The shop OAuth work enables:
1. Authenticated Etsy shop connections with PKCE flow
2. Secure token storage with AES-GCM encryption
3. Listing sync from Etsy to local products
4. Token refresh on expiry

This is intentionally packaged as Phase 1 backend validation before the queue planning UI work begins.

## Changes

### Backend
- **ShopsController**: MVC controller with routes for shop CRUD, Etsy OAuth callback, and sync
- **ShopService**: Business logic for shop management, OAuth flow, and listing sync
- **EtsyApiService**: Correct Etsy v3 API integration using proper endpoints and headers
- **TokenEncryptionService**: AES-GCM encryption for tokens at rest
- **OAuthStateStore**: In-memory PKCE state management
- **DI Registration**: All services wired in Phase1Api with proper lifetimes
- **Program.cs**: Added `AddControllers()` and `MapControllers()` for MVC routing

### Tests
- **EtsyApiServiceTests**: Verify correct API endpoints, `x-api-key` header, and snake_case JSON deserialization
- **ShopServiceTests**: Verify business logic for OAuth flow, shop management, and listing sync
- **ShopsControllerTests**: Verify controller actions, auth enforcement, and response types
- **TokenEncryptionServiceTests**: Verify round-trip encryption, tamper detection, and nonce freshness
- **DiResolutionTests**: Verify all services can be resolved from the DI container
